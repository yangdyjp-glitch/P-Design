# 图序 · AI 小红书设计工作台

从文案与真实素材，到可编辑的小红书图文。AI 自动决定画面、分页与技能，执行检查后呈现。0.5.0 增加 [登录与独立账户](docs/accounts.md)：管理员创建普通账户，每个账户独立保存项目、素材与设计记录。

换电脑接续开发，请先读 [HANDOFF.md](HANDOFF.md)，包含首次运行、AI配置、源码入口、发布步骤和当前限制。

0.5.5 增加 [我的项目删除入口](docs/project-deletion.md)：桌面项目项右侧、手机「菜单 → 我的项目」均可删除，支持目标备份与确认；最后一个项目删除后显示空工作区，并处理刷新缓存和自动保存的冲突。

0.5.4 增加 [原分页保护](docs/pagination-policy.md)：已明确分页的文案保持原页数、顺序和每页内容，让图片适配页面，不能为了放图自行增页；仅未分页文案由 AI 安排。三个预案、自动修正与网页应用共用此规则。

0.5.3 将三个预案的主题色统一为途洋 LOGO 深蓝，保留各自排版原则和图片来源规则；实际照片保持原色。[颜色及近似取色说明](docs/style-presets.md)。

0.5.1 增加 [任务阶段与画面进度](docs/job-progress.md)：显示正在调整的目标画面及准备、配图、设计、检查、保存等实际阶段；网页检查按真实结果逐页显示计数。

0.5.2 修复 [预案一漏用上传图片](docs/upload-coverage.md)：整套设计使用全部上传图，AI 自行分配页面；生成、服务端和网页应用前核对逐张覆盖，漏图进入既有自动修正。单图修改保持原范围。

Railway 部署默认需要账户登录，配置与验证见 [Railway 接入说明](docs/railway.md)。推荐启动命令为 `npm run start:railway`，此前带 sites-env 预加载的长命令也已兼容；需要配置 Railway 服务端 AI 密钥。原 Sites 站点仍沿用原认证与存储。

Railway 可通过服务端 `DATABASE_URL` 接入 Supabase PostgreSQL，自动建表并将卷里的旧数据导入空的业务 schema；图片继续保存在现有卷。设置及验收见 [Supabase 接入说明](docs/supabase.md)。此能力需部署本次代码并核对健康接口，不能仅凭添加变量认定已生效。

- Railway 使用管理员创建的账户登录，服务端与本机缓存均按账户隔离；原 Sites 保留平台身份路径。
- 保留右侧文案编辑；明确分页保持原分页，未分页才由 AI 安排。构图、配色、字重、照片安排和必要示意素材由 AI 判断。
- 14 个完整设计模块由 AI 按需加载与使用，界面无需选择任务类型、主技能或排版参数。
- 完整技能和脚本在隔离的托管环境执行，密钥始终保留在服务端。
- AI 渲染自检与网页独立检查通过后自动呈现；有新文案时保留最新内容，旧结果不覆盖新版本。
- 保留版本恢复、2160×2880 PNG、ZIP、可编辑 HTML 和项目备份。

0.3.1 已合入 `main` 发布，改为 [每张图独立的补充要求](docs/page-notes.md)：切页分别保存，点击「发送并修改本图」或按 Ctrl / ⌘ + Enter，仅调整当前图；整套设计保留为顶部独立入口。2026-11-08 用户确认没有需要保留的项目并授权发布；实际生产就绪以部署和公网验证为准。

0.4 已合入 `main` 发布，新增 [上传图裁剪保护与联网配图](docs/photo-policy.md)：上传图片最多裁剪 20%，自动检查至少保留 80% 的原图面积；可不上传图片，选择让 AI 从网上找实景配图。应用搜索的照片另行标记、保留来源，不受上传图裁剪上限限制。实际生产就绪以部署和公网验证为准。

0.4.1 新增 [三个固定风格预案入口](docs/style-presets.md)，放在新建图文的「整套初始方向」，当时先保留三个待设定位置。预案配置集中保存，选择随项目保留，任务固定采用提交时的风格版本。

0.4.3 为三种预案配置不同排版原则：上传图优先适配原图，联网图围绕实景主体与留白构图，纯文字根据段落和信息关系重新组织整张画面。AI 根据实际素材与内容选择布局并记录原因，各有检查重点。此前 0.4.2 的图片来源、裁剪保护及自动检查继续生效；具体规则见上述说明。

原 [Sites 站点](https://tuxu-design-studio-20261106.phd-yang.chatgpt.site) 保留所有者私有范围；[Railway 站点](https://p-design.up.railway.app/) 使用独立账户工作空间。生产就绪以实际部署及公网验证为准。本仓库保存源码和技能资源，不包含 AI 凭证或用户作品。原 Sites 部署记录见[部署记录](docs/deployment.md)。

开发需要 Node>=22.13。首次运行 `npm ci`、`npm run build`，按[开发与部署说明](docs/setup.md)初始化本地数据库，再运行 `npm run dev`。本地地址为 http://127.0.0.1:5173 。类型检查运行 `npx tsc --noEmit`，构建运行 `npm run build`。开发凭证放在被忽略的 `.env.local`，生产凭证通过 Sites 的服务端秘密配置管理；网页代码无需填写密钥。当前本地真实AI还需要技能上传清单和开发转发服务 `scripts/dev-ai-proxy.mjs`，详见[交接文件](HANDOFF.md#4-新电脑本地真实-ai)。生产站点不经过本机。

`design-skills/` 包含14个模块的完整说明、脚本、模板、字体、参考及各自许可。`node scripts/pack-skills.mjs` 从本仓库打包技能；`node scripts/upload-skills.mjs` 用已配置的服务端API凭证上传。打包结果位于被忽略的 `outputs/skill-release/`。上传文件ID和网站运行密钥不进入本仓库。

原 Sites 生产站点必须沿用 `.openai/hosting.json` 的身份，不重复创建，需单独执行 Sites 发布。Railway 的 main 推送可能触发自动构建；未挂持久化卷时，先备份项目再发布。独立部署者应在自己的环境重新配置资源和秘密。

详见UPGRADE.md、QA.md和THIRD_PARTY.md。签名回调已实现；公开可达并配置回调前，执行任务时保持网页打开，重新打开可继续。未提供小红书账号发布或评论功能。
