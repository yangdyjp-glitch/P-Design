# 文案优化、确认与主动技能选择

0.7.0 在新建图文前增加文案准备。入口是完整工作区，不再要求用户在同一个弹窗填写文字、照片和方向。

1. 只输入原始文案，点击「开始优化文案」。AI 依据本次内容自行判断表达与组织方式。
2. 实际采用写作技能，输出完整可编辑优化稿、简短变化说明，并独立对照原稿审校。优化稿不自动成为设计稿。
3. 用户可以编辑优化稿，点击「确认文案，进入配图」。确认后的每页文字及页数成为设计输入。
4. 上传照片或选择联网实景，再选择原有三个预案或 AI 自行判断。AI 继续执行构图、渲染、独立视觉复核与网页检查。

配图步骤可以返回修改文案，已有图片、预案与补充保留。修改原稿后需重新优化；只编辑优化稿可以重新确认。刷新从已保存的准备阶段继续。已有项目直接进入原编辑器，不强制重新润色，右侧文案与本图要求继续保留。

## 主动使用技能

网站共有 20 个模块，其中写作阶段可调度 7 个，视觉阶段保留原有 14 个，`xhs-writer` 为共同模块。

| 模块 | 本次优化的职责 |
| --- | --- |
| xhs-writer | 小红书内容主线、读者与组图阅读 |
| copywriting | 标题、重点与具体读者价值 |
| copy-editing | 信息完整性、逻辑与编辑范围 |
| humanizer-zh | 有实际问题时改善空话、重复与翻译腔 |
| content-research-writer | 确有研究需求时检索、引用与区分来源 |
| content-strategy | 有多主题或系列需求时组织主线 |
| social | 借鉴适合中文小红书的开头与组图叙述方法 |

前三个是文案核心模块，需实际载入完整包并读取指定参考；六个新增模块均须给出本次采用或跳过的具体理由。被采用的模块必须实际载入，登记 `SKILL.md`、能力卡中的真实参考文件和具体编辑手法，再与最终使用报告核对。不能只列名字，也不为凑数量把七个完整流程串行执行。可选模块按需加载，最多七个；选择在同一写作请求内完成，不增加专门的模型选技能请求。

通用规则优先于上游例子和偏好：不带入固定产品、机构、作者经历、营销指标或样例数字；不强迫表情、夸张标题、问卷与资料补写。原稿中已有事实不因此被外部证实。缺信息只在说明中提出，不把猜测或占位符塞进成稿。

`content-research-writer` 的上游在核对时未声明许可，因此本机按用户要求安装上游版本，网站只包含独立编写的集成规范，不分发原文。来源与许可见 [writing-sources.json](../design-skills/writing-sources.json) 及该目录的 `PROVENANCE.md`。

## 分页、审校与确认边界

- 原稿带（1P）、P1、第1页或独立 `---` 时，逐页优化，原页数、顺序和归属不变，不为未来照片拆页、合页或跨页搬运。
- 未分页原稿可提出 1–20 页完整结构；用户确认后同样保存固定分页。后续视觉设计不能重新拆页来放图片。
- 独立审校使用单独的 Responses 请求、同一已配置模型与独立上下文，不接收写作者的自评或技能方案。检查事实与确定程度、信息覆盖、分页、中文表达及本次范围五项。
- 审校发现实质问题时最多自动修正一次，并重新登记手法、重新审校；仍未通过、审校格式不完整或请求失败均不能确认。模型在结果中自填“通过”无效。
- 服务器保存审校来源哈希、实际优化稿哈希与任务归属。确认接口只接受本账户、本项目、同一原稿的已通过任务，并检查项目版本与固定页数；客户端伪造确认不能越过步骤。
- 用户可以手动编辑已通过的 AI 稿。手动内容由用户确认采用，记录 `manuallyEdited`，不声称人工改动后再次经过独立审校。模型审校本身也不是事实真伪或审美保证。
- 改变原稿使旧提案失效，迟到结果不能覆盖新原稿或已编辑的优化稿。新流程确认前，服务端同时拦截图片上传与视觉任务；既有素材返回时保留。

完成的项目备份作为新可编辑作品导入，不信任备份内的任务身份或审校凭据；未确认的文案准备备份保留原稿和编辑稿，需重新优化。

## 实现与运维

| 文件 | 职责 |
| --- | --- |
| `src/copy-wizard.js` / `public/copy.css` | 三步创建、编辑确认、素材与预案保留 |
| `src/copy-workflow.js` | 主动调度、分页、结果及审校校验、准备状态规范 |
| `server/copy-agent.ts` | 托管写作会话、资源按需加载、独立审校、一次修正及取消清理 |
| `server/copy-workflow.ts` | 创建文案任务与可信确认接口 |
| `server/routes.ts` / `server/webhooks.ts` | 所有权、版本、流程门槛、摘要及回调匹配 |
| `server/skills.ts` | 20 模块目录；新写作模块不会自动混入锁定文案的视觉任务 |
| `tests/copy-workflow.test.mjs` / `tests/accounts.test.mjs` | 执行、审校、恢复、SQLite 与 PostgreSQL 归属及门槛回归 |

新增 `kind=copy`、`POST /api/projects/:id/confirm-copy` 与项目 JSON 内 `copyFlow`，复用现有项目和任务表，不需要数据库迁移或新密钥。旧任务不改写为新约定。

文案环境只预载三份核心写作包，不安装字体、浏览器或额外运行包，不上传照片。可选技能只在实际选中时附入。独立审校取消/删除与托管会话清理保留句柄，共享技能不删除。GET 连接中断最多保留两次重试，写入错误不盲目重发。

Railway 启动发现旧清单缺新增写作模块时，使用卷内上传缓存补齐 20 个技能加共享字体，并按包哈希复用资源。完整自带清单仍需维护上传记录。`/api/health` 应为 `skillsReady=skillsTotal=20`，账户能力含 `copyOptimization.version=1`。安装到运营者本机和让网站直接调用分别处理，网站使用者无须安装本地技能。

文案优化和画面设计各算一个任务，现有每人每天 10 次限制继续执行。独立审校与参考读取会增加用时和 API 用量；文案审校与视觉审美是两个阶段，不能用文字检查替代实际看图。没有配置可靠生产回调时，处理期间保持网页打开；重新进入可继续。验证证据与实际耗时见 [QA.md](../QA.md)。
