# 每张图独立的补充要求（0.5.6 更新）

右侧「本图补充要求」属于当前选中的一张图。每张图使用自己的 `requirements` 字段，切页、云端保存、项目备份与导入均保留这份文本。旧版 `project.brief` 保留为整套初始背景，不自动复制到每张图，避免把旧要求误分配给某一图。

## 使用

1. 在左侧选择要修改的图。
2. 填写本图要求，例如「本图照片完整显示，不要裁切」。
3. 点击输入框下的「发送并修改本图」，或按 Ctrl / ⌘ + Enter。
4. AI 只制作、渲染和检查这张图，通过后自动更新。其他图的文案、版式、图片和补充要求保留。

输入即保存，发送才开始修改。空白要求不能发送；已有任务处理时显示等待原因，避免重复提交。顶部「AI 设计整套」仍用于整套重新设计，新建时的「整套初始方向」与逐图要求分开。

「上次本图修改」只显示当前项目、当前页的单图请求，包含已发送原文、状态和具体改动，整套任务不能充当发送记录。输入框显示的是可编辑要求，浅色占位示例不代表已经发送。输入的新要求与上次发送内容不同，会提示点击发送。自动修正显示原请求，而非内部纠错提示。

## 本次要求的执行与对照

0.5.6 新单图任务在已保存快照中冻结 `pageRevision={version:1,pageId,request}`，自动修正继承同一约定；旧任务不强加新字段。当前请求优先于旧页要求、初始背景及普通构图偏好；锁定原文、图片来源、主题蓝、上传图裁剪下限及单页范围继续优先。

AI 先看原图，再把本次要求拆成具体目标并调整；「易读」要求需诊断阅读顺序、分组、层级和行宽，不以无关或象征性修改交差。结果需提供 `revisionReview`，逐项记录要求、是否满足、实际改动和观察证据。漏填、错误目标页、旧请求、未满足、原 HTML/CSS 完全相同却报告已修改，均进入原有一次自动修正；仍失败则不应用。

托管 `check-images.mjs` 同时生成本图实际对照：`revision-before/after.png`、360px 预览、`page-revision-audit.json`，并把记录写入渲染清单。截图对照使用保留的图片定位、缩放、背景与字体缩放设置；记录实际字号、行高、字重、位置和像素差异。仅改类名、注释等造成源码不同而成图相同，不能报告「已修改」。原图确实满足时可以返回 `already_satisfied`，但成图必须不变，界面明确说明本次未改动。没有完整 HTML/CSS 母版，或母版文案与当前文案不一致时，如实标记无可靠原图对照，不能声称原图已满足。

逐项目标由同一设计 AI 自检；像素对照证明实际发生画面变化，不能独立证明主观审美提升。仍保留网页对原文、越界、重叠、图片加载和裁剪的独立检查。没有新增额外评审模型调用、人工视觉开关、密钥或数据库迁移。

## 范围约束

- 单图请求为 `kind: revise`、`workflow: automatic`、`scope: page`，`pageIds` 必须只有当前一页。
- 服务端仅从已保存项目取该页的原文和要求，不把其他页放入该任务的锁定文案。
- 单图结果必须返回同一页 ID、相同文字与顺序，不能新增、删除、重新分页或返回其他页。
- 浏览器只合并目标页的 HTML/CSS 和图片安排，检查也只针对该页；不替换整个项目的页面数组。
- 自动修正继承原单图范围，不能变为整套或切换目标。一次修正上限、原文检查、资源权限和版本冲突保护继续生效。
- 优先保留目标页已使用的图片，再补充最近上传的素材，避免较早的在用图片被最近上传列表挤掉。
- 每张图记录最近应用的 AI 任务，修改第二张后仍能正确识别第一张已经应用的结果，避免刷新后重复应用。
- 导入备份会保留各图要求，并重置原云端版本、冲突状态及旧任务标记，作为新项目保存；旧版备份也适用。
