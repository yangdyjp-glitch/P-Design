# 三个固定风格预案

新建图文的「整套初始方向」提供三个固定风格预案。0.4.2 启用预案一「实景编辑」，预案二、三继续待设定；默认仍可用「AI 自行判断」。原自由输入保留为「本次补充」，只用于当前整套图文。右侧要求继续按图独立保存。

## 预案一：实景编辑

用户授权配置预案一，具体方向由 AI 根据既有实景图片诉求、整套变化要求和通用定位确定。它适用于不同主题与产品，不预置机构或课程信息。

| 方面 | 已保存的风格 |
| --- | --- |
| 气质 | 清晰、自然、可信，带编辑设计感 |
| 配色 | 暖白 `#F5F1E8`、深墨 `#24342D`，少量苔绿 `#607C62`；明确品牌色优先 |
| 字体 | 已加载的 TY Sans 中文字重，醒目标题与清楚的正文层级 |
| 图片 | 优先相关实景，保留自然色彩；没有合适照片时使用同系统文字排版 |
| 构图 | 按内容选择大标题与主图、图文分区、正文、清单、对比、步骤或路径 |
| 系列 | 统一字体、配色和间距，改变主图位置与信息结构，避免连续三页套同一版式 |
| 装饰 | 克制使用细线、必要色块和原文数字，避免依靠重复圆角卡片与装饰填满画面 |

1080×1440 母版试排以封面标题 96–144px、内页标题 72–100px、正文 38–48px 为起点，实际按 360px 阅读图调整，正文过多优先分页。完整规则保存在 `src/style-presets.js` 的 `preset-1`，风格版本为 2。

选择后入口展开通俗风格说明，项目页显示选中预案。查看待设定预案不会替换已选风格，也不会开启搜图。应用仍遵守原文、事实、80% 原图保留和单图范围等底层约束；实景优先不等于强制联网或生成图片。

## 后续逐一配置

统一配置文件为 `src/style-presets.js` 的 `STYLE_PRESETS`。三个稳定 ID 分别是 `preset-1`、`preset-2`、`preset-3`，不要更换或复用 ID。

- `name`：显示名称；当前为中性的预案一、二、三。
- `summary`：入口上的简短风格介绍；`description` 为选中后显示的通俗说明。
- `direction`：已确认的完整视觉要求，可写配色、字体、构图、图片处理与系列变化。空值表示待设定；只有填入确认后的规则，入口才自动变为可选择的预案。
- `version`：每次修改已确认的风格后递增，便于识别任务实际采用的版本。

每个预案独立保存在仓库中，经原有构建和发布流程提供给网站使用者；不是访客各自浏览器里的临时偏好。当前不提供访客编辑全站规则的入口。完善预案时只改对应条目，不改变其他预案。界面代码和服务端共用同一份目录，更新后执行 `npm run build`。

## 数据与 AI 行为

项目保存 `stylePresetId`，随项目本机缓存、云端 JSON 和备份保留。未选预案或旧项目以 `null` 表示自动判断。服务端拒绝未知 ID 和待设定预案，不从浏览器提交的任意 `stylePreset` 对象读取风格规则。

创建任务时，服务端从目录解析 ID，将该版本的完整规则保存为任务快照 `stylePreset`，并传入托管环境的 `project.json`。同一任务及其自动修正使用同一份快照；之后修改目录不改变已提交任务。再次主动发起设计时采用当时发布的目录版本。

预案只规定视觉方向。原文保真、素材真实性、上传图至少保留 80% 面积、搜图授权和单图范围优先于任何风格；单图补充要求仍只作用于该图。三个预案共用同一套自动技能选择与检查流程。

## 验证

运行 `npm run test:presets`，以及原自动流程、图片规则、访客与结果校验检查。`npm run qa:visitor` 验证旧项目兼容、待设定/伪造预案拒绝；不会推进付费 AI。入口需另查桌面与 390px 手机布局，确认查看预案不提交表单、不清空文案。

0.4.1 只验收入口与数据连接。0.4.2 的预案一需要另用真实内容检查照片处理、原文、系列变化和实际输出，记录见 `QA.md` 及忽略的 `qa/railway/preset-one/`。预案二、三仍未完成，不能用预案一的测试替代。
