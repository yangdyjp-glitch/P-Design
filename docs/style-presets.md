# 三个固定风格预案

新建图文的「整套初始方向」提供三个预案。图片来源继续分别为上传、联网实景和完全无图；0.4.3 根据用户进一步要求，为三者配置不同的排版原则。AI 必须观察实际素材与原文关系，决定版式，而不是只换配图来源。规则由服务端解析并随任务版本保存。「AI 自行判断」保留原先的自由设计和搜图选项，本次补充用于整套，右侧要求按图独立保存。

0.5.3 起三个预案统一使用途洋 LOGO 蓝。颜色集中保存在 `src/style-presets.js` 的 `PRESET_THEME`：主色 `#021539`，浅底 `#FAFCFF`、浅蓝 `#EDF3FC`、正文深蓝灰 `#18253C`、分隔线 `#CAD6E8`、深底白字 `#FFFFFF`。主色来自用户上传的接待区照片中 LOGO 蓝色主体的近似取色，受实拍光线影响，**不是已核验的官方 VI 色号**；提供标准值后替换同一常量并递增三个规则版本即可。

统一的是标题、主要色块与强调元素的蓝色体系，不给照片套蓝色滤镜，也不把三种排版合成同一模板。不得用其他技能的示例配色或从照片另取的颜色替换主题色，不自动添加 LOGO 或品牌文案。AI 在设计计划记录实际颜色用途，服务端将可信主题随结果保留，网页应用采用该轮保存的主题；旧任务的修正继续沿用原快照。现有已排版作品不自动重绘，重新设计使用新版本。

0.5.4 起，三个预案共同遵守：**已明确分页的文案保持原分页，让图片适配页面，不能为了放图自行增页。** 原页数、ID、顺序和每页全部文案归属均固定，优先调整原页内图框、图文比例与留白。只有未分页输入才可由 AI 安排页数，修正不放宽；托管环境、服务端与网页应用均检查。当前规则版本为 7 / 4 / 4，详见 [分页保护](pagination-policy.md)。

| 预案 | 图片来源 | 界面与执行要求 |
| --- | --- | --- |
| 预案一：上传配图 | 仅 `source=upload` | 上传 1–8 张，整套全部使用，由 AI 分配页面；关闭搜图与生图，上传图至少保留 80% 面积 |
| 预案二：联网配图 | 仅 `source=web` | 隐藏上传入口；选择即授权搜图，必须取得并展示实际网络照片，保存来源，可灵活裁切 |
| 预案三：纯文字排版 | 无图片 | 隐藏图片入口；关闭搜图与生图，不允许照片、插画、SVG 插图、canvas 或图片背景 |

图片来源优先于普通视觉要求。预案一、二允许部分内页不放图。0.5.2 起，预案一新建整套任务必须实际使用每张上传图，预案二仍至少展示一张实际搜索照片；单图修改只处理目标页，不把整套所有素材强塞进当前页。渲染记录必须见证所需照片真实可见，不能用隐藏图片满足要求。缺上传图在提交前提示；联网未取得可用照片时不能用无图结果冒充成功。旧作品和旧任务不自动套用新清单，详见 [覆盖检查](upload-coverage.md)。

## 三种排版原则

| 预案 | 画面的起点 | 构图策略 | 重点检查 |
| --- | --- | --- | --- |
| 一：原图优先的编辑排版 | 实际上传图的比例、主体、原有文字与细节 | 宽图用接近原比例的通栏图与文字带；竖图可配侧栏；截图优先大幅独立展示，正式文字与原图分区 | 原图面积、主体与截图文字、图框比例、独立文字区可读性 |
| 二：实景主导的视觉叙事 | 内容需要的场景，以及实际搜索照片的主体与留白 | 大幅主图、满版实景、偏轴图文或留白中的标题；背景复杂时用独立实色文字区 | 主体是否保留，叠字位置的真实明暗与纹理，实景与原文是否匹配 |
| 三：文字主导的信息设计 | 标题长度、段落密度、原文已有的清单/对比/步骤关系 | 大字主视觉、单列解释、短清单网格、语义分栏；重新分配全部画面，不留照片占位 | 标题与正文层级、阅读顺序、段落宽度、无图后的空间是否完整 |

这些是决策原则，不是每页固定模板。网上照片不适合叠字时应分区，纯文字没有清单时不能强做清单，上传素材也不能全当作横幅风景。每个版式必须有来自当前素材和内容的理由，三者不会因同一文案或同为实景就自动共用同一张网格。

### 预案一：保留原图特征

预案一使用途洋 LOGO 蓝的编辑风格，保留宽图、竖图、方图、截图、信息密集原图和低清晰度图片的不同处理方法。上传图裁剪不超过 20%，完整显示要求保留 100%；不通过改图、遮罩或叠正文绕过限制。适用于通用主题与产品，不预置课程信息。

| 方面 | 已保存的风格 |
| --- | --- |
| 气质 | 清晰、自然、可信，带编辑设计感 |
| 配色 | 途洋 LOGO 深蓝 `#021539`，配浅底、浅蓝分区与高对比正文 |
| 字体 | 已加载的 TY Sans 中文字重，醒目标题与清楚的正文层级 |
| 图片 | 仅用上传素材，优先与内容相关的实景，保留自然色彩与事实 |
| 构图 | 按内容选择大标题与主图、图文分区、正文、清单、对比、步骤或路径 |
| 系列 | 统一字体、配色和间距，改变主图位置与信息结构，避免连续三页套同一版式 |
| 装饰 | 克制使用细线、必要色块和原文数字，避免依靠重复圆角卡片与装饰填满画面 |

1080×1440 母版以封面标题 96–144px、内页标题 72–100px、正文 38–48px 起排，实际按字形和 360px 阅读图调整，正文过多优先在原页调整分区；只有未分页文案可考虑增页。当前 `preset-1` 风格版本为 7，统一蓝色主题并保留全部上传图的页面分配与覆盖检查；不能因照片细节密集或配色不同自行弃图。

### 预案二：让照片参与构图

先确定主题与阅读任务，再通过现有搜索工具找适合的实景。实际查看原图，判断主体位置、场景延伸、可用留白、主色、明暗和背景纹理。主体与文字的关系决定图框、焦点与裁切；照片合适时可大幅铺展或在自然留白放标题，复杂背景不直接承载正文。长正文页可改用侧图或较窄实景条，避免每页相同满版背景。

主题色固定为途洋 LOGO 蓝，依据照片明暗安排蓝白文字区与深浅底，不另从照片中选主色。封面标题约 96–156px，正文约 38–48px 起排。当前 `preset-2` 版本为 4，来源与裁切语义不变，明确分页不能因配图拆页。

### 预案三：由文字建立画面

标题、关键词和原文已有数字可以成为主视觉；连续解释、短清单、对比和步骤采用不同的阅读结构。必须按内容重新安排文字宽度与留白，不保留删去图片后空出的半页。短标题约 120–180px、长标题约 80–120px、正文约 38–48px 起排，最终按真实预览决定。长段落不挤进三窄栏，也不把所有文字套进等大卡片。

配色统一为途洋 LOGO 蓝，字重根据内容决定，只用原生文字与必要 CSS 分组元素。原文没有的编号、结论、标签和口号不能为了构图补造。当前 `preset-3` 版本为 4，继续禁止图片、SVG 插图、canvas 和图片背景，并保留明确的原分页。

## AI 的观察与检查

有图时记录实际尺寸、比例、类型、主体、已有文字、明暗与复杂度；无图时记录标题、正文密度与真实语义关系。AI 在 `design-plan.json` 保存这些观察和逐页选择版式的理由。观察必须来自实际文件，不能把文件名、搜索描述或来源模式冒充看图。

共用的原文、字体、边界、图片加载、裁剪和来源校验继续执行；视觉检查按预案各有重点，并实际查看 180px 缩略图、360px 阅读图及总览。该设计记录和视觉判断不是新增的硬编码审美评分，自动结构检查也不能代替看图。单图修改与自动修正始终保持原任务范围；修正继续用原任务保存的风格版本。

选择后入口显示对应说明，上传入口及搜图状态自动匹配；切回「AI 自行判断」恢复此前手动搜图选择。选择联网或纯文字时，先前在表单中选过的上传文件不会随新项目提交。项目素材面板也遵守同一预案的来源限制。

## 后续逐一配置

统一配置文件为 `src/style-presets.js` 的 `STYLE_PRESETS`。三个稳定 ID 分别是 `preset-1`、`preset-2`、`preset-3`，不要更换或复用 ID。

- `name`：显示名称。
- `summary`：入口上的简短风格介绍；`description` 为选中后显示的通俗说明。
- `direction`：已确认的完整视觉要求，可写配色、字体、构图、图片处理与系列变化。空值表示待设定；只有填入确认后的规则，入口才自动变为可选择的预案。
- `version`：每次修改已确认的风格后递增，便于识别任务实际采用的版本。
- `imageMode`：`upload`、`web` 或 `none`，由可信目录决定；未选预案为 `auto`。

每个预案独立保存在仓库中，经原有构建和发布流程提供给网站使用者；不是访客各自浏览器里的临时偏好。当前不提供访客编辑全站规则的入口。完善预案时只改对应条目，不改变其他预案。界面代码和服务端共用同一份目录，更新后执行 `npm run build`。

## 数据与 AI 行为

项目保存 `stylePresetId`，随项目本机缓存、云端 JSON 和备份保留。未选预案或旧项目以 `null` 表示自动判断。服务端拒绝未知 ID 和待设定预案，不从浏览器提交的任意 `stylePreset` 对象读取风格规则。

创建任务时，服务端从目录解析 ID，将完整规则和图片模式保存为任务快照 `stylePreset` / `imageMode`，只传入允许来源的素材；不能通过客户端搜图开关覆盖来源限制。生成配图工具在三个固定预案中均关闭，搜图工具只对联网预案开放。同一任务及其自动修正沿用相同快照；旧快照没有模式时保留原来的自动行为。再次主动设计时采用当时发布的目录版本。

服务端结果校验同时拒绝错误来源、纯文字预案的图片，以及整套配图预案未实际展示照片的结果。网页自动应用与导出前再次检查来源。新搜索图片的来源取自服务端素材记录，不能用客户端标签伪装。原文保真、事实和单图范围继续生效，三个预案共用同一套自动技能与检查流程。

## 验证

运行 `npm run test:presets`，以及原自动流程、图片规则、访客、数据库与结果校验检查。`npm run qa:visitor` 验证旧项目兼容、伪造预案拒绝、三个来源模式的保存与任务快照；不会推进付费 AI。入口需另查桌面与 390px 手机布局、上传必填、来源联动和原文保留。

实际设计、来源与手机阅读证据见 `QA.md` 及忽略的 `qa/railway/preset-one/`。结构校验不能替代对具体成图的审美判断，也不代表全部题材与长文已穷举。
