# 我的项目：删除与空工作区

0.5.5 在桌面「我的项目」每一项右侧增加垃圾桶按钮。手机从「菜单 → 我的项目」进入相同列表。点击名称进入项目，点击垃圾桶只选择该项目删除，不会先切换当前正在编辑的项目。

确认窗口显示项目名称和画面数，默认焦点放在「取消」。用户可以先下载该项目的完整备份；即使它不是当前项目，备份也使用所选项目的文案、图片和版式。「确认删除」执行后不可撤销，已有备份可以重新导入。处理期间禁用重复操作，失败时保留本机项目并显示错误，可重试。

删除当前项目后选择相邻项目；删除其他项目保留当前页面和编辑内容。最后一个项目也可删除，此后显示带「新建图文」「导入项目」的空工作区，不自动重建示例项目。首次进入尚无项目的账户也使用同一入口。

## 保存、缓存与范围

- 删除与云端保存共用顺序队列：先结束已经发出的保存，再删除；成功后忽略这个旧项目对象的后续自动保存，避免重新创建。
- 删除成功后更新本机项目列表并保存。重新载入云端时，移除已经在其他设备删除且没有本机新修改的缓存；尚未同步的本机编辑保留供备份并标记冲突，不覆盖或重新创建已删云端项目。
- 服务端仍按当前账户隔离删除项目和素材，并停止该项目未完成的任务。上传已经开始但项目尚未成功保存的素材也可按所属项目清理，不能删除其他账户的素材。
- 既有「设计记录」和已完成交付文件沿用原留存行为；可从设计记录下载交付文件，但不能自动应用回已删除的项目。本功能不是清空全部账户历史。
- 不新增数据库迁移、AI 调用、密钥或账户权限。原文、分页、三个预案及图片裁剪规则保持现有约定。

## 实现与验证

`src/app.js` 提供项目入口、目标确认、备份与空工作区；`public/projects.css` 提供桌面和手机样式；`src/project-management.js` 处理选择与缓存合并。`src/cloud.js` 串行保存/删除并隔离旧任务返回，`server/routes.ts` 处理所属项目及未完成上传的清理。

`tests/project-management.test.mjs` 验证删除当前、非当前和最后一个项目，缓存恢复、未同步内容保护、保存与删除的先后、失败重试和重复删除。账户测试分别用 SQLite、PostgreSQL 检查越权拒绝、项目素材删除、任务停止和旧版本不能重新创建。浏览器及本机 HTTP 验证见 `QA.md`，产物在忽略的 `qa/railway/project-delete/`。生产用户项目不作为删除样例。
