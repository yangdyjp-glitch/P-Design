# 0.5.2：预案一使用全部上传图片

此前预案一只要求整套至少展示一张上传图，并允许 AI 择优选用。两张图片都成功上传、也被 AI 查看后，仍可能只用其中一张；现有裁剪检查核对的是已用图片，无法发现未使用的素材。

新建预案一的整套设计任务时，服务端将本项目全部上传图（1–8 张）的 ID 写入 `snapshot.imagePolicy.requiredUploadIds`。AI 实际查看每张图并按图像特征与原文分配页面，不能因展板文字、配色或构图偏好自行舍弃。`design-plan.json` 应记录逐图观察及实际使用页码。原文、真实身份、上传图至少保留 80% 面积和独立文字区规则继续生效；环境照不能冒充团队合照。

不要求每一页放照片，也不要求所有图片集中在一页。每张必用图至少实际展示一次；重复同一张、仅写 `photoAssetId`、隐藏图或不可辨认的小缩略图不能作为替代。构图和照片用途继续由 AI 决定，不新增视觉设置。

## 执行与边界

- `server/routes.ts` 从可信素材记录创建清单，并在用户自己的任务接口返回 `requiredUploadIds`。自动修正沿用父任务清单及保存的风格版本。
- `automaticAssets` 对整套上传任务完整传入全部素材；超过 8 张明确报错，不再默默选一部分。项目上传入口提前限制总数。其他模式保留原有选图方式。
- `server/agent.ts` 为每张图提供真实文件与可按需加载的资源。素材记录或文件缺失时，任务在启动 AI 前失败，不静默跳过。
- `server/image-check-runner.mjs` 实际渲染结果，基于真实图片加载、可见性及裁剪检查核对覆盖清单，缺图写入失败记录。
- `server/design-result.ts` 核对实际 `<img data-asset-id>`，`renderAudit` 再核对真实图片检查记录。漏图进入现有的一次自动修正，仍未通过则保留当前作品并报告原因。
- `src/cloud.js` 将同一清单交给网页应用前的真实页面检查；网页按共享规则核对实际可见的上传图片，未通过不能覆盖当前作品。

单图修改不创建整套必用图清单，不扩大到其他页，也不为补齐整套素材塞入全部照片。联网实景、纯文字和未选预案的 AI 自行判断模式保持现有规则。旧任务没有清单时继续原约定，旧作品不会在更新或导出时被迫重排。用户重新执行整套设计后才采用预案一版本 5。

## 接续验证

`node --test tests/*.test.mjs` 覆盖双图漏用、同图重复、仅登记编号、加载/可见性、完整输入与按需加载、文件缺失、一次修正、超过 8 张拒绝、旧任务与单图边界。然后执行 `npx tsc --noEmit` 与 `npm run build`。

真实 AI 验证应在隔离本地项目使用两张实图，核对实际结果中的两张 ID、图片可见比例、原文、服务端渲染记录与网页自动应用。生产检查只核验发布、静态资源和既有项目留存，不修改用户现有作品。证据保存在忽略目录 `qa/railway/upload-coverage/`，具体验证范围见 [QA.md](../QA.md)。不增加密钥、数据库迁移或新付费服务。
