# 明确分页的文案保持原分页

0.5.4 的底层规则：**已明确分页的文案保持原分页，让图片适配页面，不能为了放图自行增页。** 对三个预案及自由设计均生效，自动修正也不能放宽。

新建时用 `（1P）`、`(1P)`、`P1`、`第1页` 等页码标记，或单独一行 `---` 分隔页面，会保存 `paginationMode=fixed`。只标记一页也视为固定一页。保留原页数、页面 ID、页面顺序，以及每页文案块的 ID、文字、归属和顺序；不能新增、删除、拆分、合并页面，也不能维持总页数却将段落移到另一页。

没有页码或分隔线的完整文案保存为 `paginationMode=auto`，仍由 AI 决定 1–20 页，全部原文及整体顺序继续锁定。无需使用者额外调整开关。旧项目、旧备份缺少此字段时保守保留当前已存在的页面，不猜测或恢复历史拆页前的结构。显式手工调整页面后也保留调整后的分页。

图片通过图框、图文比例、分区与留白适配原页。上传图至少保留 80% 原面积、全部必用上传图、来源限制和文字可读性仍同时成立；不能靠过度裁剪、缩成不可读缩略图、漏图、删字或隐藏文字通过。原页确实无法容纳时报告未完成，进入原有一次自动修正，仍失败则保留原项目。

## 执行与检查

- `src/pagination-policy.js` 统一识别分页、解析可信模式并检查逐页归属，`src/engine.js` 共用同一拆分逻辑。
- `src/app.js`、`src/cloud.js` 在创建、导入、备份及云端保存中保留模式；界面说明固定分页含义，不新增人工参数。
- `server/routes.ts` 从已保存项目确定任务模式，忽略任务请求自带的模式；关联修正沿用原任务快照。升级前已经提交的任务保留原合同，新提交的旧项目任务保留当前页面。
- `server/agent.ts` 及三个预案的共享分页规则要求先遵守分页再构图，不再无条件建议增页。AI 在实际设计计划记录输入输出页数及每页归属。
- 托管环境 `check-images.mjs` 从真实 DOM 读取每页 `data-copy` 顺序，与原页对照；服务端 `server/design-result.ts` 独立比较页数、ID、顺序与每页原文，拒绝不符结果；浏览器 `src/ai-workflow.js` 应用前再次检查。原文字符另由既有保真检查校验。

新规则不修改数据库结构，不增加 API 密钥，也不自动改动已有成图。已有七页作品仍按当前七页保留，不能仅凭本规则自动猜测恢复为之前六页；要恢复时需使用原始六页文案或对应历史版本。

## 验证

`tests/pagination-policy.test.mjs` 覆盖多种分页标记、单页标记与未分页区别、旧项目及冻结修正、增删拆合、同页数跨页移动、三个来源模式及浏览器应用拦截。自动流程检查实际的拒绝—一次修正—恢复原分页路径。完整验证运行 `node --test tests/*.test.mjs`、`npx tsc --noEmit`、`npm run build`。真实 AI、网页及发布记录见 `QA.md`，产物不进入公开仓库。
