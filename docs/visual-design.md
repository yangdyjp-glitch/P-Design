# 0.6.0 视觉技能、构图调度与独立审美复核

所有新建的整套设计、单图修改、封面、排版精修与模板任务，都采用同一套强制视觉流程。它由服务端固定，不增加使用者的视觉参数。纯文案、参考分析和单独素材生成不冒充完成了整页设计；旧任务保留提交时的约定。

0.6.1 继续加强十个可选模块的主动匹配、真实参考载入和逐页方法登记，见 [专长选择说明](specialist-routing.md)。下面的四个核心模块与独立复核仍是基础流程。

## 必经流程

1. 载入小红书主流程 `xiaohongshu-design`、Victor 视觉设计 `victor-design`、海报构图 `xhs-poster-composition`、中文排版精修 `xhs-design-polish` 四个完整技能。按内容继续选择其余模块，实际封面补用 `xhs-cover-lab`，使用视觉参考时补用参考契约。14 个模块仍可用，不要求全部串行执行。
2. 设计 AI 阅读相关说明与参考，每页内部比较三种可行构图，决定阅读任务、第一焦点、阅读顺序、图片角色、图文比例和结构。用 `submit_visual_plan` 登记具体采用的手法、原因及来源。整套建立共同视觉语言与内容驱动的变化；单图只调度目标页，窄要求维持原有版式范围。
3. 实际制作、浏览器渲染并执行原有技术检查。最终 HTML/CSS 与原始页面设置的 SHA-256 绑定到对应 360×480 手机成图。构图登记或实际成图缺失时不能进入成功状态。
4. 发起另一条独立的、无工具的视觉模型请求。它只收到实际成图、原文、当前要求、品牌及来源边界；单图有可靠旧母版时另附真实修改前预览。它看不到设计者的自评、构图解释或技术通过结论。
5. 独立复核逐页检查构图、信息主次、中文排版、图文关系、疏密留白及范围；多页另检查系列关系。存在实质问题则进入既有的一次自动修正，重新登记、实际渲染和复核。仍未通过，或复核出错、未完成，保留原作品并说明原因，不绕过检查直接应用。

一次修正预算与技术检查、网页应用纠错共享，不是每类错误各增加一次。若第一次技术纠错已经使用预算，随后审美复核失败也不会开启第二轮重做。

## 审美判断的口径

- 从真实照片和文案关系出发。环境照、证据照不自动成为大幅主视觉；教学阶段、流程、分组等关系应在构图中可读。
- 不把“标题＋居中大图＋等权正文”视作默认合格，也不以增加装饰、套盒子或堆叠手法代替设计。完成度高的克制版式可以通过。
- 手机阅读视图检查中文断行、长段分组、标题与正文层级、照片对文字的挤压、空白的用途及视觉节奏。轻微可改进项记为建议，实质且处于授权范围的问题才要求重做。
- 单图仅复核当前要求与其影响。“标题一行”不能成为全套改版的理由；广泛的易读性、审美与构图要求则应检查整个目标页。仅看到一张图时不能臆测全套重复。
- 原文、原分页、途洋蓝、照片真实性及来源规则优先。上传图至少保留 80% 原图面积，明确要求完整展示时保留全部；联网实景照片按其来源规则处理。审美建议不能借机增页、改写或捏造标签。

## 可查记录与校验

任务详情显示四个实际载入的核心技能、构图决策，以及独立复核的逐页观察与建议；处理中区分「构图调度」和「独立视觉复核」。失败的复核也可查看。完成摘要保持精简，完整详情按需获取。

`snapshot.visualDispatch` 保存服务端实际收到的工具登记、轮次、文件包哈希和载入状态；最终结果保留 `visualDesign`、`visualReview` 与最多两轮 `visualReviewHistory`。复核记录包含实际页面、模型、独立调用标记和成图哈希，网页应用前也要求可信服务端复核为通过且目标匹配。登记的来源路径和手法是 AI 的工作记录，不等于对每条阅读命令的执行证明。

复核通过后再次获取实际 PNG 比较指纹，避免检查后换图。一次纠错未变化的页面可复用紧邻上一轮的不可变图片文件，但最终渲染清单与源码哈希仍必须对应当前结果；不接受任意旧轮次的成图。

审美复核使用相同已配置模型的独立请求与独立上下文，没有引入另一个模型供应商。它能减少明显的构图问题，也可能误判，不能保证每一张达到用户偏好。新增一个模型复核阶段会增加时间和用量；发生一次修正时还会重新复核。继续复用原渲染环境和已有预览文件，保留 0.5.7 的载入与文件交付优化。

实测还发现收取文件时短暂断线会终止已通过复核的任务。现在只有服务端 GET 读取的连接失败允许保留任务，后续正常轮询继续原有读取，同一任务最多保留两次；不会因此重新生成或重复审美调用。写入请求、无效凭证、额度不足及非连接错误不走这一恢复分支。持续失败仍安全结束，不能将它解释为对任意网络故障的无限重试。

## 开发与部署

- `src/visual-design.js`：统一策略、构图登记与六项复核结构校验。
- `server/agent.ts`、`server/skills.ts`：强制技能载入、调度工具、修正与任务推进。
- `server/visual-review.ts`：独立视觉上下文、真实成图读取、结构化输出与修改建议。
- `server/image-check-runner.mjs`：实际手机预览、源码指纹及既有技术检查。
- `server/design-result.ts`、`src/ai-workflow.js`：服务端与应用前校验。
- `server/webhooks.ts`：独立复核响应的回调定位，兼容 SQLite / PostgreSQL。回调链路未配置时仍需保持网页打开或返回继续处理。
- `src/cloud.js`、`src/job-progress.js`：自动阶段和复核详情。
- `tests/visual-design.test.mjs`、`tests/automatic-workflow.test.mjs`：策略、独立调用、范围、一次修正、失败关闭、成图替换与旧轮次不可变文件复用检查。

没有数据库迁移、新密钥或手动审美开关。独立复核响应完成后删除，取消时尝试取消并删除。取消先保存停止状态，再请求远端清理；会话清理异常不阻断私有输入清理，未成功删除的输入保留句柄供后续处理，共享技能文件保留。新策略只用于新任务，已有作品和旧任务不自动重新生成。实际验证与部署状态见 [QA.md](../QA.md)。
