# 0.6.1 主动选择设计专长

新设计与单图修改继续使用四个核心视觉模块，再由 AI 主动匹配十个可选模块。它必须在确定构图前逐项判断适用性，并把实际采用的手法对应到页面；不增加使用者的风格选择或审批步骤。历史作品和旧任务保持原样。

## 选择原则

| 页面的实际内容或任务 | 优先采用的专长 |
| --- | --- |
| 封面与首图 | `xhs-cover-lab` 的封面结构与视觉证明 |
| 已查看的设计样稿或内置优秀参考 | `xhs-reference-contract` 的视觉规范提取 |
| 明确的流程、阶段、比较或嵌套关系 | `baoyu-infographic` 的信息布局方法 |
| 长文、知识、清单、叙述和实证 | 从 `xhs-note-creator`、`auto-redbook`、`blcaptain-style-skill` 选择合适的结构与视觉语法 |
| 适合的封面主视觉或插画组织 | 考虑 `baoyu-cover-image`、`baoyu-xhs-images`、`xhs-images-design`，遵守当前来源限制 |
| 内容策划与阅读组织 | 考虑 `xhs-writer`，锁定原文时不能执行改写 |

每页新设计或整体重排至少采用一个与内容相符的专长。常规在整套范围增加一到三个模块，同一方法可服务多页，总载入上限为八个，包括四个核心模块。不能为凑数量强行调用，也不要求十个候选全部执行。对于没有用户设计参考的新方向，AI 还应查看合适的 Victor 内置参考板，判断是否提取参考契约；实拍照片本身不算设计样稿。

只有明确局部的单图微调可以沿用已有构图并说明原因，例如调整标题字号或照片裁切。广泛的“更易读”“改善审美”与重新构图不能用微调理由绕过专长选择。局部例外有请求范围和关键词检查；具体视觉效果仍由独立看图复核。

## 方法参考与流程应用

“方法参考”表示读取技能的真实说明、模板或布局资料，把合适的方法落实到可编辑 HTML。它不等于执行该模块的全部工具、生图、文案或发布流程。三种当前预案均不执行图片生成：上传与网络照片保留其真实性，纯文字不擅自新增插画。可以借鉴生成类技能的信息组织方法，但不能报告生成了实际不存在的素材。

原文、固定分页、途洋蓝、上传图至少保留 80% 原图面积、明确要求完整展示及单图边界优先。上游技能的固定主题、自动分页、改写和照片处理示例不能覆盖这些约定。

## 实际约束与记录

- 策略由服务端放入新任务快照；自动修正继承原约定。旧快照不被追加强制规则。
- `submit_visual_plan` 要求十个候选各有一条采用、跳过或受限记录，记录具体原因。选中的技能必须实际加载到设计环境，登记 `SKILL.md` 及能力卡列出的至少一份实际参考文件，并在对应页登记具体手法。
- 最终实际使用报告必须包含这些选择。仅列出技能名称、未加载模块、无对应页面、缺参考路径或把方法参考称作实际生图，均不能通过相应校验。
- 详情的“专长技能选择”显示采用数量、对应页、参考方式及十项选择理由。“已评估十项”不等于“执行十项”。失败结果也可显示已登记的选择。
- 载入状态和包指纹由服务端记录；引用路径、方法、任务标签与采用理由是设计 AI 的登记，不是逐条文件阅读命令的执行证明。服务端不能单靠这些文字证明审美改善。
- 成图仍交给独立请求查看实际手机预览，不接收设计者自评。继续沿用一次自动修正预算和不通过则不应用的边界。

选择记录随原设计请求完成，不为选择步骤单独增加模型请求。额外资料加载及处理仍可能增加时间；独立复核的用时和限制见 [视觉设计说明](visual-design.md)。没有新增数据库迁移、密钥或人工视觉参数。

## 接续入口

`src/specialist-routing.js` 集中维护十项能力卡、参考路径、内容匹配、微调例外与结果一致性；`server/agent.ts` 提供调度指令和构图工具结构。`server/design-result.ts` 与 `src/ai-workflow.js` 分别在服务端和网页应用前校验；`src/cloud.js` 展示只读详情。相关检查在 `tests/specialist-routing.test.mjs` 与 `tests/automatic-workflow.test.mjs`。发布和真实验证见 [QA.md](../QA.md)。
