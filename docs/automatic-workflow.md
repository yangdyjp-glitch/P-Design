# 0.3：以文案为中心的 AI 自动设计

用户本轮要求减少人工设置，保留右侧文案编辑，尽量由 AI 自行判断画面并执行检查。该版本延续原有项目、素材、导入备份和高清导出格式。

## 使用流程

1. 新建图文，粘贴原始文案；图片和补充要求均为选填。
2. 点击「开始 AI 设计」。已有项目可编辑右侧文案后点击「AI 设计整套」。0.3.1 的右侧「本图补充要求」独立属于当前图，使用旁边的「发送并修改本图」局部更新，详见 [逐图要求](page-notes.md)。
3. AI 判断视觉方向、分页、图片安排和合适技能，完成实际制作、渲染与检查。
4. 网页再次检查实际画面。文案版本仍一致且检查通过时，方案自动呈现并保存，可继续编辑文案或下载。

主界面移除画面/检查选项卡、构图选择、颜色和字号控件、照片裁切滑块、手工页面编排、技能选择及任务类型选择。画面缩放、预览、素材上传、下载和版本恢复属于查看、输入与保存操作，继续保留。右侧要求按图独立保存和发送，无需选择技能或视觉参数。

0.4.1 按用户新增要求，在「整套初始方向」加入三个固定风格预案入口，目前均待设定。确认后的预案决定整套视觉方向，AI 继续自行决定具体排版及技能、自动执行检查。预案未设置或未选择时沿用自动判断，详见 [风格预案](style-presets.md)。

## 技能按需加载

14 个完整技能在服务端配置就绪，目录元数据提供给 AI。自动任务初始只装载主流程、排版检查和共享字体。需要其他能力时，AI 通过 `load_design_resource` 取得完整 ZIP，解压并读取真实 SKILL.md、参考和脚本；没有把技能简化成提示词标签。

首次实际测试发现，把全部 ZIP 一次传入会返回 400，并说明异步托管环境的能力与文件快照超出 50 MiB 总量。因此初始文件预算限制在 45 MiB，预留输入与能力描述空间；可选模块和较大图片在环境连接后按需加入。单轮最多加载 8 个相关模块，通常 2–6 个。文件 ID 只在服务端任务快照中使用，不放浏览器或模型的项目输入。

本次项目最近 8 张图片供 AI 判断，上传原图继续保留。大图不因初始化预算被丢弃，可通过相同加载工具读取。生成示意图由 AI 按需决定，单轮至多一张，并标记为 AI 生成；不能冒充真实课堂、人物身份或成果。

「本次可用」与「实际使用」分开。已完成记录只统计实际装载且由 AI 报告使用的模块，不把所有可用模块算作执行过。

## 原文与自动分页

自动流程允许重新分为 1–20 页。服务端从原始快照推导每页文案，不采纳模型另写的 copy 字符串；每个 data-copy ID 必须恰好出现一次，保留全部文字、数字、标点和整体顺序。未知 ID、改字、遗漏、重复、乱序和越界素材引用均拒绝。

现有非自动接口继续保留原来的单页/范围限制。自动分页不是放开其他用户或其他项目的数据。

## 自动检查与修正

- 托管 AI 必须实际渲染所有页面，查看手机阅读预览，检查原文、边界、遮挡、图片和字体，并输出 `render-manifest.json`。
- 服务端要求本轮结果及渲染记录有效、页面数匹配、状态 passed、无 issues 或网络加载失败。渲染文件是过程证据，仍需网页独立检查。
- 网页用真实 DOM 和已加载字体再次检查文字、越界、裁切、重叠和图片加载，再自动应用。
- 格式或渲染记录未通过时，在同一托管会话内修正一次；网页发现新的显示错误时，可创建一次关联修正任务，同时传入已校验的上一版 HTML/CSS 和实际问题。这两条分支共用单轮一次修正上限，修正任务不能再继续派生或生成新图。
- 任务数和并发额度继续生效，关联修正任务计入每日额度。遇到网络、权限、额度错误不会盲目循环生成。
- 浏览器渲染检查和技术校验不能证明审美最优；设计报告应说明实际视觉判断与检查，不伪造检查记录。

自动应用前、渲染检查后均核对项目版本。用户生成期间编辑文案、要求或素材时，旧方案保留但不会覆盖最新内容。自动应用也保留版本记录，可以恢复。

## 源码与验证

- 界面与自动应用：`src/app.js`、`src/cloud.js`、`src/ai-workflow.js`。
- 资源加载、实际执行和修正：`server/agent.ts`。
- 原文与分页校验：`server/design-result.ts`。
- 额度、关联修正与项目权限：`server/routes.ts`。
- 纯策略与渲染记录校验：`server/automatic-workflow.ts`。


真实任务、网页自动呈现、图片导出与手机布局需另外验证，记录见 QA.md。不要把单元检查或已连接密钥等同于真实设计成功。
