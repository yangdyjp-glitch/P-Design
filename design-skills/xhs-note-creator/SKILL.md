# 小红书笔记创作技能

## 本地安装约定

这是已安装的专长模块。与下方原版流程冲突时，当前用户要求、已确认方案和本段优先；按需读取 [本地专长调用规则](../xiaohongshu-design/references/specialist-policy.md)。

- 原版主题、工具与参考可继续使用；示例品牌、行业、字体、配色、照片、页数与字数只作为本次可选方案，不是通用硬规则。
- 完整锁定原文只做保真制图，授权创作或改写时才重写文案；不强制先写长文、添加视频或重复确认已选方向。
- 选择生图流程时优先使用本环境内置 imagegen；不默认调用原版中未配置的外部接口。
- 上传、发布、评论和账号操作只在用户另行明确要求时执行，不能因完成制图自动进入这些步骤。

本机依赖与验证状态见 `runtime.json`；来源、许可和本地改动见 `sources.json`。

根据用户提供的资料或需求，创作小红书笔记内容、生成精美图片卡片。卡片渲染完成后，发布必须交由独立的 **`xhs-publisher`** 技能通过浏览器自动化完成（详见第五步）；不要使用其他技能或临时拼接发布流程，以免因步骤较多导致失败。

> 详细参数文档见 `references/params.md`

## 工作流程

### 第零步：创建选题文件夹

在生成任何 Markdown 或图片文件前，先在项目根目录创建本次选题文件夹：

1. 使用当天日期创建一级目录，格式为 `YYYYMMDD`，例如 `20260513/`。
2. 从本次选题中提炼一个具体关键词作为目录名，不要使用泛化的 `subject`。目录格式为 `<keyword>_N`，例如 `20260513/skincare_1/`；如果同一关键词目录已存在，则使用下一个可用编号。
3. 本次生成的所有文件都必须放入该选题目录，包括第一步的纯文本笔记 `note.md`、第二步的渲染用 Markdown（如 `content.md`）以及后续生成的 `cover.png`、`card_1.png` 等图片。

关键词命名要求：使用一个能概括选题的短词，优先用英文或拼音小写，必要时用数字；只使用字母、数字、连字符或下划线。示例：护肤选题用 `skincare_1`，咖啡选题用 `coffee_1`，AI 工具选题用 `aitools_1`。

示例结构：

```text
20260513/
└── skincare_1/
    ├── note.md
    ├── content.md
    ├── cover.png
    ├── card_1.png
    └── card_2.png
```

### 第一步：撰写小红书笔记内容

根据用户需求和资料，创作符合小红书风格的内容：

**标题**：不超过 18 字，吸引眼球，可用数字/疑问句/感叹号增强吸引力。

**正文**：段落清晰，点缀少量 Emoji（每段 1-2 个），短句短段，结尾附 5-10 个 SEO 标签。不要使用任何 Markdown 语法！！只用 emoji、换行和全角符号排版。

---

### 第二步：生成渲染用 Markdown 文档

**注意：此 Markdown 专为图片渲染设计，禁止直接使用上一步的笔记正文。**

文档结构：

```markdown
---
emoji: "🚀"
title: "封面大标题（≤15字）"
subtitle: "封面副标题（≤15字）"
---

# 标题

内容...

---

# 标题

内容...

```

上方示例生成：一张封面（emoji + title + subtitle）+ 两张正文卡片（各自的 `#` 标题作为卡片标题）。

分页策略选择：
- 内容需精确切分 → 用 `---` 手动分隔，配合 `-m separator`
- 内容长短不稳定 → 生成普通 Markdown，使用 `-m auto-split`

---

### 第三步：选择主题风格

渲染前，**必须**向用户展示所有可用主题并让用户选择。使用 AskUserQuestion 工具，将 9 种主题作为选项列出：

| 编号 | 主题值 | 名称 | 视觉特征 |
|---|---|---|---|
| 1 | `sketch` | 手绘素描 | 手绘线条风格，温暖自然 |
| 2 | `default` | 默认简约 | 浅灰渐变背景，干净利落 |
| 3 | `playful-geometric` | 活泼几何 | Memphis 设计风格，色彩丰富 |
| 4 | `neo-brutalism` | 新粗野主义 | 粗框线条、强对比色块 |
| 5 | `botanical` | 植物园自然 | 绿植元素，自然清新 |
| 6 | `professional` | 专业商务 | 商务蓝色调，简洁正式 |
| 7 | `retro` | 复古怀旧 | 暖色调复古感，年代氛围 |
| 8 | `terminal` | 终端命令行 | 深色背景，代码终端风格 |
| 9 | `pink-notebook` | 粉色笔记本 | 粉色格子纸、手绘贴纸、玫瑰棕文字 |

**展示方式**：使用 AskUserQuestion 工具，将 9 种主题作为选项列出，每个选项包含名称和简短描述，等待用户选择后再进入渲染步骤。

---

### 第四步：渲染图片卡片

根据用户在第三步选择的主题，执行渲染命令：

```bash
python scripts/render_xhs.py <选题文件夹>/content.md -t <用户选择的主题> -o <选题文件夹> [options]
```

**默认分页**：`separator`（按 `---` 分隔）

常用示例：

```bash
# 使用用户选择的主题 + 手动分页
python scripts/render_xhs.py 20260513/skincare_1/content.md -t sketch -o 20260513/skincare_1

# 自动分页（推荐内容长短不定时）
python scripts/render_xhs.py 20260513/skincare_1/content.md -t playful-geometric -m auto-split -o 20260513/skincare_1
```

生成结果保存在选题文件夹中：`cover.png`（封面）+ `card_1.png`、`card_2.png`...（正文卡片）。如果不传 `-o`，渲染脚本默认把图片输出到 Markdown 文件所在目录。

**分页模式**（`-m`）：`separator`、`auto-split`、`dynamic`

> 完整参数说明见 `references/params.md`

---

### 第五步：发布小红书笔记（必须交由 xhs-publisher 技能）

本技能**已不再内置任何发布脚本，也不再涉及 Cookie 或平台接口调用**。早期版本曾通过 `publish_xhs.py` 直接调用小红书接口发布，但直接调用平台接口风险极高（易触发风控、账号受限），已整体移除。

卡片渲染完成后，发布必须交由独立的 **`xhs-publisher`** 技能完成：它通过 Playwright 驱动**真实浏览器**，完整模拟真实用户的扫码登录、点击、输入、上传与点「发布」操作，全程不碰任何私有接口或签名，安全性远高于直接调接口。发布流程步骤较多，使用其他技能或自行拼接流程容易遗漏状态检查、上传顺序、隐私设置或发布按钮点击逻辑，导致失败。

接续方式：将本技能产出的 `cover.png`、`card_*.png`、标题与正文交给 `xhs-publisher`，由其走浏览器发布流程（默认「仅自己可见」，发布后由用户在小红书端自行决定是否公开）。

> 本技能只负责「写文案 + 渲染卡片」；发布动作必须调用 `xhs-publisher` 技能。不要使用其他技能执行发布流程，发布步骤较多，容易因遗漏环节而失败。

## 技能资源

### 脚本
- `scripts/render_xhs.py` — 渲染脚本（主推，9 主题 + 多种分页模式）
- `scripts/render_xhs_v2.py` — 渲染脚本 V2（备用，7 种渐变色彩风格）
- `scripts/render_xhs.js` / `scripts/render_xhs_v2.js` — Node.js 版渲染脚本（参数与 Python 版基本一致）

> 发布能力已迁移至独立的 `xhs-publisher` 技能（浏览器自动化），本目录不再保留任何发布/Cookie 脚本。

### 模板与样式
- `assets/cover.html` — 封面 HTML 模板
- `assets/card.html` — 正文卡片 HTML 模板
- `assets/styles.css` — 公共容器样式
- `assets/themes/` — 各主题 CSS 文件

### 参考文档
- `references/params.md` — 完整参数参考（主题/模式）
